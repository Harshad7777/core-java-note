## Basics

### What is Time Complexity?

Time complexity is a way to measure how much time an algorithm takes to execute as the input size increases.

In simple words, it tells us how efficient an algorithm is.

It is usually represented using Big O notation.

### Why is it important?

- helps compare algorithms
- improves code understanding
- helps write optimized code
- reduces execution time
- useful in coding interviews
- helps understand CPU usage

Example: if two programs solve the same problem, we choose the one with lower time complexity.

### Prerequisites

Before learning time complexity, we should know:

- basic coding
- loops and conditions
- mathematical functions
- algorithm understanding
- resource utilization

### Why execution time alone is not enough

Suppose two developers write the same algorithm:

- Developer A → 3 seconds
- Developer B → 5 seconds

This does not mean Developer A is always better because execution time depends on:

- machine speed
- processor
- RAM
- compiler
- system load

So we compare algorithms by their growth rate, not the actual machine clock time.

### How to judge a better algorithm?

We check resource utilization.

Two major resources are:

1. Processor utilization
2. Memory utilization

- Time complexity → CPU/processor usage
- Space complexity → memory usage

### How to count processor operations?

Generally:

- variable initialization = 1 operation
- arithmetic operation = 1 operation
- comparison = 1 operation
- assignment = 1 operation
- return = 1 operation
- loop increment/decrement = 1 operation

```java
int a = 10;   // 1 operation
int b = a + 5; // 1 arithmetic + 1 assignment
if (a < b) { // 1 comparison
    return a; // 1 return
}
```

## Big O

### What is Big O?

Big O is a notation used to represent the time complexity of an algorithm.

It describes how execution time grows as the input size increases.

Examples:

- O(1)
- O(log n)
- O(n)
- O(n²)

### Rules of Big O notation

#### Rule 1: Ignore constant values

Constants do not matter.

Examples:

- O(2n) = O(n)
- O(100n) = O(n)

#### Rule 2: Consider the highest growth term

Ignore lower-order terms.

Example:

- O(n² + n + 10) = O(n²)

Because n² grows faster than n and 10.

## Common Time Complexities

| Big O | Name | Example |
| --- | --- | --- |
| O(1) | Constant | array index access |
| O(log n) | Logarithmic | binary search |
| O(n) | Linear | single loop |
| O(n log n) | Linearithmic | merge sort |
| O(n²) | Quadratic | nested loop |
| O(2ⁿ) | Exponential | recursive Fibonacci |
| O(n!) | Factorial | traveling salesman |

## Examples

### 1. O(1) – Constant Time

Execution time does not change with input size.

```java
int arr[] = {10, 20, 30};
System.out.println(arr[1]);
```

Only one access is done, so time complexity is O(1).

### 2. O(log n) – Logarithmic Time

Input size reduces repeatedly.

Example: binary search.

```java
int binarySearch(int arr[], int key) {
    int low = 0;
    int high = arr.length - 1;

    while (low <= high) {
        int mid = (low + high) / 2;

        if (arr[mid] == key)
            return mid;

        if (arr[mid] < key)
            low = mid + 1;
        else
            high = mid - 1;
    }
    return -1;
}
```

Time complexity = O(log n)

### 3. O(n) – Linear Time

One loop runs over the input.

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

Time complexity = O(n)

### 4. O(n²) – Quadratic Time

Nested loops.

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i + " " + j);
    }
}
```

Time complexity = O(n²)

### 5. O(n log n)

This is common in efficient sorting algorithms.

Examples:

- Merge Sort
- Heap Sort
- Quick Sort (average case)

Formula:

O(n log n)

### Example of O(n log n)

```java
void printPairs(int n) {
    for (int i = 1; i <= n; i++) {
        int j = 1;
        while (j < n) {
            System.out.println(i + " " + j);
            j = j * 2;
        }
    }
}
```

Outer loop → O(n)
Inner loop → O(log n)

Total = O(n log n)

### Quick comparison (best to worst)

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)

Lower complexity means faster algorithm.

## Interview Questions

### Q1. Why do we use Big O?

To measure algorithm efficiency.

### Q2. Which is better: O(n) or O(log n)?

O(log n) is better.

### Q3. Which sorting algorithms are O(n log n)?

- Merge Sort
- Heap Sort
- Quick Sort (average case)

### Q4. Is a nested loop always O(n²)?

No. It depends on the loop execution count.

- Big O ignores constants and focuses on growth rate
