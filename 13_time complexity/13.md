# Time Complexity

---

## Q. What is Time Complexity?

Time Complexity is a way to measure how much time an algorithm takes to execute as the input size increases.

In simple words:
It tells us how efficient an algorithm is.

Time complexity is usually represented using **Big O Notation**.

---

## Why is Time Complexity Important?

---

Time complexity is important because:

* Helps compare two algorithms
* Improves code understanding
* Helps write optimized code
* Reduces execution time
* Useful in coding interviews
* Helps understand processor usage

Example:
If two programs solve the same problem, we choose the one with lower time complexity.

# Why Execution Time Alone is Not Enough?

---

Suppose we have an algorithm named **XYZ**.

Two developers implement it:

* Developer A → Executes in **3 seconds**
* Developer B → Executes in **5 seconds**

At first, we may think Developer A's solution is better.

But this is not always true.

Why?

Because execution time depends on:

* Machine speed
* Processor
* RAM
* Compiler
* System load

Developer A may have a fast machine.
Developer B may have an old machine.

So we cannot judge an algorithm only by execution time.

---

# How to Judge a Better Algorithm?

---

We check **resource utilization**.

Two major resources:

## 1. Processor Utilization

How many operations CPU performs.

## 2. Memory Utilization

How much memory algorithm uses.

* Time Complexity → CPU/Processor usage
* Space Complexity → Memory usage

# Q. What is Big O?

---

Big O is a notation used to represent the time complexity of an algorithm.

It describes how execution time grows as input size increases.

Example:

* O(1)
* O(log n)
* O(n)
* O(n²)

---

# Rules of Big O Notation

---

## Rule 1: Ignore Constant Values

Constants do not matter.

Example:
[
O(2n) = O(n)
]

[
O(100n) = O(n)
]

---

## Rule 2: Consider Highest Growth Term

Ignore smaller terms.

Example:

[
O(n^2 + n + 10)
]

Largest term = (n^2)

So:

[
O(n^2)
]

---

# Common Time Complexities

---

| Big O      | Name         | Example             |
| ---------- | ------------ | ------------------- |
| O(1)       | Constant     | Array index access  |
| O(log n)   | Logarithmic  | Binary Search       |
| O(n)       | Linear       | Single loop         |
| O(n log n) | Linearithmic | Merge Sort          |
| O(n²)      | Quadratic    | Nested loops        |
| O(2ⁿ)      | Exponential  | Recursive Fibonacci |
| O(n!)      | Factorial    | Traveling Salesman  |

---

# 1. O(1) – Constant Time

Execution time remains same.

Example:

```java
int arr[] = {10,20,30};
System.out.println(arr[1]);
```

Only one access → **O(1)**

---

# 2. O(log n) – Logarithmic Time

Input gets reduced repeatedly.

Example: Binary Search

```java
int binarySearch(int arr[], int key) {
    int low = 0;
    int high = arr.length - 1;

    while(low <= high) {
        int mid = (low + high) / 2;

        if(arr[mid] == key)
            return mid;

        if(arr[mid] < key)
            low = mid + 1;
        else
            high = mid - 1;
    }
    return -1;
}
```

Time Complexity = **O(log n)**

---

# 3. O(n) – Linear Time

One loop.

```java
for(int i = 0; i < n; i++) {
    System.out.println(i);
}
```

Time Complexity = **O(n)**

---

# 4. O(n²) – Quadratic Time

Nested loops.

for(int i = 0; i < n; i++) {

# 5. O(n log n)

# Example of O(n log n)

```java
void printPairs(int n) {
    for(int i = 1; i <= n; i++) {
        int j = 1;
        while(j < n) {
            System.out.println(i + " " + j);
            j = j * 2;
        }
    }
}
```

Outer loop → **O(n)**
Inner loop → **O(log n)**

Total:

[
O(n \log n)
]

# Quick Comparison (Best to Worst)

---

[
O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(2^n) < O(n!)
]

Lower complexity = Faster algorithm

# Interview Questions

---

### Q1. Why do we use Big O?

To measure algorithm efficiency.

### Q2. Which is better: O(n) or O(log n)?

**O(log n)** is better.

### Q3. Which sorting algorithms are O(n log n)?

* Merge Sort
* Heap Sort
* Quick Sort (average case)

### Q4. Nested loop always O(n²)?

No. Depends on loop execution.
